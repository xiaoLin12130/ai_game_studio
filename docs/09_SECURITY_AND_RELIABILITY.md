# 09｜安全、隔离、恢复与可观测性

## 本地优先

MVP 默认本地单用户。除非未来明确批准，不上传项目源代码、素材、Prompt、DSH 会话或日志到第三方云服务。GitHub 只用于用户主动配置的代码版本和阶段复审，不包含密钥和私有运行状态。

## 文件系统隔离

- 每个项目配置唯一规范化根路径。
- 所有文件操作先进行路径归一化和根路径边界检查，防止路径穿越。
- 任务契约声明允许读写范围。
- 禁止模型自由拼接任意绝对路径执行写入。
- 文件修改保留 diff、备份/原子写入和操作记录。

## 项目锁

- 项目写锁：同一项目只允许一个写入者。
- 构建锁：构建期间禁止改动构建输入。
- 资源处理锁：同一资产派生任务避免竞争覆盖。
- 锁有 owner、任务 id、创建时间、续租和过期恢复策略。

## 恢复

- Studio 数据必须可独立恢复，不依赖某个 DSH Session。
- 任务 checkpoint 记录已完成步骤、输出路径、Git SHA、执行事件、下一步和阻塞原因。
- 恢复时先检查项目文件是否与 checkpoint 一致，再决定续跑/重试/人工介入。
- 不允许“重放全部操作”导致重复覆盖或重复构建。

## 可观测性

统一日志字段：`timestamp`、`projectId`、`taskId`、`sessionId`、`eventType`、`severity`、`operationId`、`commitSha`（适用时）、`buildId`（适用时）。日志不记录密钥、完整敏感路径或不必要的原始对话内容。

## 环境隔离

- DSH 子进程环境变量采用最小权限；避免无意继承危险环境变量。
- 不允许向 DSH 或子进程传入不必要的系统密钥。
- 构建前记录 Node/包管理器/引擎/开发者工具版本和关键环境变量摘要。
- 开发者工具可能修改项目私有配置，构建/导入后必须回读关键配置并做差异检查。

## 备份和回滚

- 重要配置先备份再写入。
- 版本控制排除构建缓存和临时产物，保留必要的可复现配置。
- 危险写入前展示影响路径和回滚办法。
- 不自动执行破坏性 Git 操作。
