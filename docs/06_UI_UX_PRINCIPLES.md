# 06｜UI/UX 产品界面原则

## UI 目标

让用户管理游戏研发，而不是管理 Agent、Session、Prompt、MCP 或底层日志。普通用户无需知道这些概念也能完成主要工作。

## 一级导航（控制在五项）

1. **工作台**：项目列表、项目阶段、下一步、风险、待审批、最近活动。
2. **游戏项目**：项目详情、需求、设计、任务、开发、测试和交付。
3. **AI 顾问**：跨项目/项目内讨论、研究任务、建议和草稿。
4. **设计与素材**：UI 设计、参考案例、素材 Inbox、全局素材库和项目素材库。
5. **决策中心**：需求冻结、变更、危险操作和发布交付审批。

知识库、Prompt 管理、DSH Session、Git Diff、Token、原始事件、MCP、日志放在项目高级视图/设置，不放一级导航。

## 项目工作台建议布局

- 顶部：项目名、阶段状态、目标平台、环境状态。
- 左侧/顶部：项目阶段导航（想法、设计、素材、原型、UI、开发、测试、交付）。
- 中央：当前阶段内容和主要操作。
- 侧边栏：AI 顾问、执行进度、需要用户决定的事项。
- 底部/抽屉：最近活动、证据、错误和高级技术信息。

## AI 顾问交互

- 自然语言输入为主，支持图片/文档/参考游戏资料附件。
- 对话中清楚区分：AI 观察、事实来源、推测、建议、待确认问题。
- AI 追问应逐步发生，不要一开始展示复杂问卷。
- 提供“保存为草稿”“创建研究任务”“提交为变更提案”等明确动作。
- 对话内容不能因为用户说“可以”就自动成为正式基线；必须明确显示审批内容和影响。

## 任务列表

用户看到任务名称、为什么要做、当前状态、是否阻塞、输出物、验收状态和下一步。高级视图才显示 DSH Session、Prompt、上下文包、工具调用、Git Diff、Token 和原始事件。

## 决策中心

每个待审批事项显示：
- 要决定什么；
- AI 为什么提出；
- 影响范围；
- 风险与可逆性；
- 证据来源；
- 批准后会执行什么；
- 拒绝后会怎样。

危险操作不能用容易误触的单击按钮；必须清楚展示操作目标和作用范围。

## 视觉设计原则

- 清晰、克制、专业，避免“AI 科技大屏”式无意义装饰。
- 状态颜色统一且语义固定；不要只用颜色表达状态。
- 优先展示用户需要做的下一件事，而不是所有后台数据。
- 空状态必须说明如何开始；错误状态必须给出恢复动作。
- 支持长任务、多个项目、宽表格和长文档；避免信息挤在卡片里。
- 提供普通/高级视图；默认普通视图。

## 可用性验收

- 新用户能在不理解 DSH 的前提下创建一个想法草稿。
- 用户能区分草稿和正式基线。
- 用户能看出任务失败是真失败还是待验证。
- 用户能定位待审批内容并理解其影响。
- 用户能看到素材来源和许可状态。
- 用户能找到项目交付物和证据。
