# 07｜游戏设计、素材与原型流水线

## 素材库结构

- 全局素材库：跨项目复用的素材记录。
- 全局 Inbox：用户暂未分类的新素材。
- 项目素材库：当前游戏批准使用的资源与加工版本。
- 原始素材区：只读保存原始文件和来源；不随意覆盖。
- 派生素材区：裁切、缩放、调色、格式转换、图集和导入引擎后的版本。

## 每个素材的最低元数据

`assetId`、名称、类型、文件格式、尺寸、帧数/动画信息、风格标签、主题标签、来源 URL/作者、许可证/使用条件、导入时间、哈希、原始文件路径、派生版本、适用平台、禁止用途、当前项目使用位置、审核状态。

许可未知必须标记 `UNKNOWN`，不能默认可商用。素材来源和许可记录要随最终交付导出。

## 素材导入流程

1. 文件类型和安全检查。
2. 哈希去重。
3. 图像/动画基础分析。
4. 尺寸、透明边缘、帧数、色彩和文件体积分析。
5. 分类和标签建议。
6. 用户/规则确认。
7. 建立原始记录和派生关系。
8. 项目使用前匹配游戏实体和视觉风格。

AI 可以给分类建议，但尺寸、格式、哈希和文件路径等确定性数据必须由程序测量。

## 素材匹配与缺失清单

素材不能只按文件名挑选。需要结合：游戏对象、动作状态、朝向、动画帧、画风、比例、透明边缘、使用位置、平台限制和许可证。

缺失素材优先顺序：
1. 现有库中合适的素材；
2. 合法且许可明确的外部素材；
3. 对已有素材进行可追溯改造；
4. 生成新素材或采用明确批准的替代方案。

不能把不匹配素材硬拼在页面里。重大风格替换需要用户确认。

## 设计流程

- 竞品/参考搜集 → 风格板 → 设计规格 → 原型 → 用户审核 → 引擎内验证 → 正式设计版本。
- 原型用于验证信息层级、布局、交互和视觉方向；不能取代目标引擎中的真实运行验证。
- UI 规格需包含设计分辨率、坐标空间、组件尺寸、锚点、间距、字体、折行、状态、滚动、安全区和交互反馈。
- 最终页面必须在目标引擎、微信开发者工具及真机门禁中验证。

## 原型验证

在全面开发前，识别最影响游戏成败的玩法假设，构建最小可玩原型。原型必须有明确问题、指标/观察方式、成功/失败条件和结论。通过后才扩展系统；未通过应调整设计，不得继续堆功能。
