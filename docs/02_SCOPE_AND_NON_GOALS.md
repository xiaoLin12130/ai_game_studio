# 02｜范围与明确不做的事情

## MVP 范围

- Windows 本地单用户应用。
- 项目工作台和项目空间。
- DSH 官方 SDK 集成、Session 生命周期和事件显示。
- DSH 可调用的 Studio 业务工具（优先只读工具，再逐步引入受控提案/执行工具）。
- 顾问对话、项目上下文、讨论草稿、研究报告。
- 正式需求/设计基线、冻结、变更申请和审批。
- 任务、依赖、任务契约、里程碑、阶段状态和中断恢复。
- 全局/项目素材库、Inbox、资产元数据、素材盘点和缺失清单。
- 页面设计规格、参考研究、原型预览和截图证据。
- 开发任务调度、文件权限、写入锁、构建锁。
- 自动化测试、构建产物校验、微信开发者工具/真机验证状态管理。
- 发布候选包、交付清单和证据归档。
- Prompt/规则/知识治理，以及现有 `AGENTS.md`、`docs/`、`memory-bank/`、`state/` 体系。

## 首个目标平台

首轮以 Cocos Creator 3.8.6 + 微信小游戏作为真实适配验证目标。应通过 Adapter/Capability 层隔离引擎和平台差异，但 MVP 不要求完整支持 Godot、Unity、Unreal 等全部引擎。

## 明确不做

- 发布后游戏数据/玩家行为/留存/收入监控。
- 微信后台数据抓取、崩溃在线监控和用户反馈聚合。
- 发布后持续顾问、在线运营建议、自动数值调整和版本迭代。
- 自研大模型 API 通信、独立 Agent Runtime、独立模型供应商路由器。
- MVP 多租户 SaaS、团队复杂组织权限、云端远程构建农场。
- 一开始覆盖所有游戏引擎和所有发布平台。
- 自动发布、自动提交审核或自动处理平台资质。

## 范围变更原则

任何新增模块必须回答：解决哪个用户痛点、属于哪个旅程阶段、为什么 MVP 必须有、增加何种风险/成本、是否能推迟。不得因为 Agent 觉得“以后可能有用”就纳入当前开发。
