# 12｜真实游戏项目复盘沉淀为系统门禁

本文件将过去微信小游戏/Cocos/Agent 开发复盘中反复出现的问题，转为 AI Game Studio 的产品要求。它不是某个游戏的当前状态报告。

## 竞品和选型

- 必须有同类游戏研究和目标平台技术可行性验证。
- HTML 原型只证明信息层级/配色/交互方向；进入引擎前必须产出坐标、单位、锚点和文本规格。
- 选型必须先跑通目标平台最小导出链路。

## 素材

- 素材入库需中文语义描述、标签、来源、许可证、平台适用性和禁用条件。
- 原始素材不可随意覆盖；派生资源必须可追溯。
- 不允许只凭文件名或单张截图盲目拼素材。

## 构建和开发者工具

- CLI build success/退出码不能证明目标平台产物真正生成且是新的。
- 使用唯一构建产物真相源；构建必须独占。
- 写后回读校验配置；检查 Build ID、哈希、时间戳和本次特有标记。
- 导入/预览/开发者工具可能运行旧包或反向修改项目配置，必须校验真实输入和输出。

## 真机和平台

- 微信端与 Web 差异包括安全区、胶囊、iOS 音频、滚动、字体、触摸、生命周期等。
- Web Mock 不代替微信环境；微信开发者工具不代替真机。
- 真机未测必须显示未验证，不能假完成。
- 分包检查实际首屏 preload 和资源加载，不只看主包尺寸。
- 平台 API 必须验证“有实现”与“实际接线”两件事。

## Cocos 工程细节

- 实测设计分辨率、坐标空间、包围盒、透明边缘、文本折行和资源加载行为。
- `.meta` 配对、Import Map、资源引用和场景导入需有检查。
- 生命周期必须有节点、事件订阅、材质、模态框和资源回收断言。
- 战斗等复杂流程使用显式状态机，避免多个 Boolean 相互冲突。

## Agent 协作

- 先读后改、锚点唯一、原子写入、写后回读、语法检查。
- 同一项目禁止多个写入会话；构建独占。
- 交接必须及时、短小、索引化；长日志和截图留路径。
- 测试脚本自身也要验证，失败必须非零退出。
- 截图关联 Commit/Build ID/时间戳；夹具图标记 `[FIXTURE]`。
- 量化脚本与视觉模型交叉验证。
- 用户逐条反馈必须逐条回执。
- 文档、代码和脚本多真相源冲突时，以真实代码和运行事实复核，并更新文档。

## 转换为门禁的要求

上面每一条都不能只留在提示词里。PHASE 06 前应将适用规则实现为可执行检查、测试、证据字段或明确的人工门禁。暂时无法自动化的规则必须保留人工验收项。
