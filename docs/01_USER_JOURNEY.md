# 01｜端到端用户旅程

## 旅程总览

1. 提出想法。
2. 与 AI 顾问自由讨论，澄清目标和限制。
3. 竞品研究、玩法分析、可行性与风险分析。
4. 形成游戏设计资料和阶段计划。
5. 用户确认并冻结正式需求基线。
6. 初始化游戏工程和环境。
7. 导入素材、盘点资源、制定缺失素材方案。
8. 完成关键玩法原型验证。
9. 完成 UI/UX 规格、视觉预览和引擎验证。
10. 按任务契约执行正式开发。
11. 持续执行代码、功能、视觉、平台和真机测试。
12. 修复问题并完成最终验收。
13. 生成发布交付包，用户自行在微信平台完成发布。

## 用户可以随时做什么

用户在任何阶段都可以继续讨论、提出新想法、询问原因或要求研究。讨论不会因为项目阶段而被禁止。但讨论默认只生成草稿/建议，不会修改冻结基线或触发写代码任务。

## 三个工作区

### A. 需求讨论区

- 用自然语言、参考图、参考游戏、文件开始。
- 支持长期顾问对话和跨会话上下文。
- 可生成研究任务和设计草稿。
- 不允许直接改变正式研发内容。

### B. 正式研发区

- 只消费用户已批准的需求基线和设计版本。
- 展示里程碑、任务、依赖、执行状态、风险和证据。
- 任务执行通过 DSH 完成，Studio 管理权限和状态。

### C. 需求变更区

- 对现有基线提出修改。
- AI 分析受影响需求、设计、素材、代码模块、任务、测试和进度。
- 展示局部返工计划、风险、成本/工期变化。
- 用户审批后生成新基线版本并创建返工任务。

## 用户的主要决策点

- 是否采用某个游戏方向/玩法方案。
- 是否冻结正式需求基线。
- 是否接受素材替换/生成/改造方案。
- 是否确认 UI/UX 设计。
- 是否授权高风险执行。
- 是否批准需求变更。
- 是否接受最终验收和发布交付包。

## 最终交付

最终交付包括：游戏源工程、目标平台发布候选构建、Build Manifest、测试报告、未完成/未验证事项、素材许可/来源记录、发布操作说明和回滚/版本说明。Studio 不替用户声称微信平台审核或发布已成功。
