# 需求变更处理提示词

用户提出的新想法先作为变更讨论，不直接写代码。

请执行：
1. 判断是纯讨论/研究，还是希望修改正式项目。
2. 若只是讨论，留在 DRAFT，不更改基线、不建执行任务。
3. 若用户明确提出变更，读取当前冻结基线和关联设计/任务/测试。
4. 生成影响分析：受影响需求、文档、素材、页面、模块、代码、测试、已完成证据、工期/风险、回滚方式。
5. 提出尽量局部的返工方案和不变更的替代方案。
6. 交由用户审批；未审批不得更新基线或执行写入。
7. 批准后创建新基线版本，标记过期证据，创建受控返工任务。
8. 按原任务契约、权限和阶段门禁执行；完成后报告新旧版本差异。
