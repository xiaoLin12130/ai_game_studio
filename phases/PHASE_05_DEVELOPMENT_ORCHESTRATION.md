# PHASE 05｜任务编排、DSH 执行与变更返工

## 目标

把正式基线拆成带契约的任务，让 Studio 调度 DSH 执行，并确保权限、依赖、状态、恢复和结果可追溯。

## 工作项

- 从基线/设计自动生成可编辑里程碑和任务树。
- 任务依赖图、关键路径、并行只读任务与串行写入任务。
- 每个任务生成 task contract：目标、输入、范围、禁止项、验收、命令、证据、回滚。
- Prompt Compiler 组合全局规则、项目规则、任务要求、相关代码/文档/素材上下文。
- 为 TASK_EXECUTION 创建隔离 DSH Session，记录 session id、工作区、版本和 checkpoint。
- 运行事件、子任务、审批、错误和最终响应在 UI 中可见。
- DSH Tool Approval 映射到工具许可界面；Studio Business Approval 仍独立。
- P0/P1/P2/P3 权限门禁；写入任务持有项目写锁，构建持有构建锁。
- 实现任务失败、阻塞、中断、恢复、重试和幂等控制。
- 将需求变更分析映射到受影响设计/任务/测试，审批后生成局部返工任务。
- Git Diff 和文件修改记录可查看、可回滚。

## 验收门禁

- [ ] 任务来源能追溯到冻结基线。
- [ ] 未批准草稿不会进入执行队列。
- [ ] 两个写入任务无法并发修改同一工程。
- [ ] 任务事件和 DSH Session 事件有映射。
- [ ] Timeout 不会被错误显示为 Runtime 已停止。
- [ ] 中断后能依据 checkpoint 恢复或安全转人工。
- [ ] 高风险操作需要审批并留痕。
- [ ] 需求变更可做影响分析并局部返工。
- [ ] 测试失败不能自动标记任务完成。
- [ ] 阶段报告、证据和 GitHub 推送完成。
