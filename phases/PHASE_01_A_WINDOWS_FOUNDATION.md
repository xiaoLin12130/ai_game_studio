# PHASE 01-A｜Windows 桌面应用基础与 DSH 真实连接状态

## 目标

在已批准的 PHASE 00 基线上，交付一个真正能在 Windows 上启动、关闭、并显示 DSH **真实**连接状态的桌面应用最小闭环。
不追求业务功能，只证明「应用能跑起来，且它显示的 DSH 状态是真的」。

## 固定基线

- 仓库：`https://github.com/xiaoLin12130/ai_game_studio`
- PHASE 00 最终批准提交：`9c8757c8e91ec10ca0fd1114408306dd72980709`（标签 `phase-00-final`）
- 本阶段分支：`phase/01-a-windows-foundation`
- 本阶段产物目录：`apps/studio/`、`evidence/phase-01-a/`

## 工作项

1. Electron 桌面应用骨架：主进程 / preload / 渲染进程三层，IPC 白名单。
2. DSH 适配层：定位运行时、执行就绪探测、把结果标准化成状态模型。
3. 最小 UI：顶部状态、DSH 状态卡片、重新检测、诊断信息、日志入口。
4. 配置与日志：用户数据目录、默认值与校验、损坏配置的显式恢复、日志脱敏与轮转。
5. 真实桌面验收：应用可启动、窗口可见、状态正确、可关闭、不残留子进程。

## 验收门禁

- [ ] 应用在 Windows 上可启动，主窗口可见。
- [ ] 界面显示 DSH **真实**状态，不使用假数据、固定字符串或模拟延迟。
- [ ] DSH 不存在 / 不可用时显示明确状态与可读原因，应用本身仍可用。
- [ ] DSH 恢复可用后，用户可重新检测并看到状态更新。
- [ ] 应用可正常关闭，退出后不残留 Studio 管理的运行时进程。
- [ ] 配置与日志写在用户数据目录，不写仓库/源码目录。
- [ ] 配置损坏时应用不崩溃，且恢复行为对用户可见。
- [ ] 单元测试 + 集成测试（真实 DSH）+ Windows 桌面冒烟测试全部通过。
- [ ] 阶段报告、证据、Git 提交与推送完成。

## 不做

- 不实现完整的 Session / Task 生命周期管理（PHASE 01-C）。
- 不接官方 MCP SDK（PHASE 01-B）。
- 不做项目管理、素材、构建、路由等功能。
- 不做正式安装包（打包冒烟作为 PHASE 01-B 的前置，见 ADR-0001 §5）。
- 不重跑 PHASE 00 的六项真实模型探针。
