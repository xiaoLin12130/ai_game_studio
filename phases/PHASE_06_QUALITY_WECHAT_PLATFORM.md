# PHASE 06｜质量门禁、构建和微信平台验证

## 目标

把过去项目中容易误判的构建、测试和真机问题转换为可执行门禁，确保“开发完成”有证据支持。

## 工作项

- 任务级静态检查、单元/集成/回归测试和测试脚本自检。
- Cocos 工程检查：资源引用、`.meta`、Import Map、场景、分辨率、生命周期和资源回收。
- 微信构建：唯一产物目录、Build ID、manifest、哈希、时间戳、配置和包体分析。
- 产物新鲜度和本次特有标记校验；避免跑旧包。
- 微信开发者工具导入/运行本次产物，记录实际版本和日志。
- 真机测试清单和证据采集；设备/系统/微信版本/步骤/截图/日志关联 Build ID。
- 安全区、胶囊、刘海屏、iOS 音频、字体折行、滚动、触摸、分包、preload、资源加载、性能检查。
- 页面视觉回归：夹具图与真实截图分离，几何量化与视觉模型交叉验证。
- 门禁状态 `PASS` / `PARTIALLY_VERIFIED` / `BLOCKED` / `FAIL`。

## 验收门禁

- [ ] 所有测试脚本失败时非零退出。
- [ ] 测试目标工程可自证，不会跑错项目。
- [ ] 构建产物 Build ID、Commit SHA、哈希和时间戳完整。
- [ ] 微信开发者工具真实运行本次产物。
- [ ] 真机测试有真实证据，或明确阻塞且不得宣称交付通过。
- [ ] 真实截图与夹具截图严格区分。
- [ ] 平台能力“实现”和“实际接线”分别验证。
- [ ] 失败项能生成修复任务并追溯到原始需求。
- [ ] 阶段报告、证据和 GitHub 推送完成。
