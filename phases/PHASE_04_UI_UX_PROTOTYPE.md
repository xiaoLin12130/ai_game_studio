# PHASE 04｜玩法原型与 UI/UX 设计工作台

## 目标

把“先设计、再预览、再确认、最后进引擎”做成系统流程，降低 UI 和玩法返工。

## 工作项

- 从正式基线识别关键玩法风险，生成最小可玩原型任务。
- 原型目标、假设、观察指标、成功/失败条件和结论必须明确。
- 建立竞品/参考截图集和可追溯来源。
- 生成 UI 页面清单、导航关系、状态矩阵和交互流。
- 页面规格包含设计分辨率、坐标、锚点、尺寸、间距、安全区、字体、折行、滚动、反馈和异常状态。
- 生成/维护线框图、视觉稿或可运行原型；所用素材必须来自资产库或有明确来源记录。
- 支持多个设计方案并排比较，用户确认后形成正式 DesignArtifact 版本。
- HTML/浏览器原型进入引擎前必须转成引擎无关规格，并在 Cocos 中做真实验证。
- 视觉审核区分主观审美和可量化几何/尺寸指标。

## 验收门禁

- [ ] 关键玩法假设经过最小原型验证或明确标记未验证。
- [ ] 页面清单覆盖正式需求所需页面和状态。
- [ ] UI 规格可供开发 Agent 直接实现，不只有一张效果图。
- [ ] 素材与页面元素的引用可追溯。
- [ ] 用户能比较、评论和批准设计版本。
- [ ] 至少一个代表页面完成目标引擎内验证。
- [ ] 浏览器预览不被宣称为微信真机通过。
- [ ] 阶段报告、证据和 GitHub 推送完成。
