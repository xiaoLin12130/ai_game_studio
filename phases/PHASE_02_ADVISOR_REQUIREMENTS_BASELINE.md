# PHASE 02｜AI 顾问、需求讨论与正式基线

## 目标

让用户可以用自然语言提出游戏想法，和 DSH 持续讨论并生成研究/设计草稿，再经明确审批冻结正式需求。

## 工作项

- 项目级长期顾问对话与 DSH Session 映射。
- 支持文本和常见文档/图片附件（具体格式受当前 DSH SDK 支持能力约束）。
- Prompt/上下文编译：项目规则、用户目标、已有事实、引用资料、当前阶段状态。
- 对话内容可保存为 IdeaDraft、ResearchRequest、DesignDraft，不自动升级为正式需求。
- 竞品研究、可行性、平台风险报告模板；事实/推测/建议分离，来源可追踪。
- 需求/设计草稿版本对比。
- 生成 GDD 初稿、核心系统清单、开发范围、里程碑和验收标准。
- 用户确认页：展示冻结内容、版本号、影响范围和未决事项。
- 实现需求基线冻结、版本哈希和不可覆盖约束。
- 需求变更提案、影响分析和审批流程初版。

## 验收门禁

- [ ] 用户只输入一句想法即可开始讨论。
- [ ] AI 追问是渐进式，不强制复杂表单。
- [ ] 讨论内容默认不修改基线、不自动创建开发任务。
- [ ] 研究报告的外部事实带来源，未验证项有标记。
- [ ] 用户可以确认、拒绝、编辑设计草稿。
- [ ] 基线冻结后不可原位覆盖。
- [ ] 新变更可以生成影响分析，但未经批准不会执行。
- [ ] Session 中断不导致项目状态丢失。
- [ ] 阶段报告、证据和 GitHub 推送完成。
