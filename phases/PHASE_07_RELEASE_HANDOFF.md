# PHASE 07｜最终验收与发布交付

## 目标

将通过质量门禁的游戏整理成用户可接收的发布候选版本和完整交付资料。Studio 不替用户执行微信平台最终发布，也不做发布后监控。

## 工作项

- 汇总正式需求覆盖率：每条需求对应设计、任务、测试和证据。
- 处理所有 P0/P1 缺陷；其他已知问题由用户确认是否接受。
- 检查最终构建与复审 Commit SHA 一致。
- 导出源工程/必要配置/资源清单/构建包/Build Manifest。
- 输出素材来源和许可证清单。
- 输出测试报告、真机报告、未验证项、风险和限制。
- 输出版本号、构建时间、目标平台、运行环境和发布操作说明。
- 提供交付包完整性校验和回滚/恢复说明。
- 用户确认交付完成后，项目状态转为 `DELIVERED`。

## 验收门禁

- [ ] 正式基线要求覆盖率可核对。
- [ ] 关键质量门禁均为 PASS；若平台条件缺失，不能标记完全交付。
- [ ] 交付构建与源码 Commit、Build Manifest 一致。
- [ ] 源工程和发布候选包可复现/可校验。
- [ ] 素材许可和来源信息随交付包导出。
- [ ] 未解决问题和未验证项完整列出。
- [ ] 用户确认接收交付物。
- [ ] GitHub 阶段推送和复审交接完成。

## 明确边界

微信平台后台最终提交、资质、审核和上线操作由用户自行完成。Studio 可以提供基于真实资料的操作说明，但不自动发布、不声称已过审。交付完成即为本产品生命周期终点。
